# SpeakCraft Navigation & Tab-Switching Performance Audit

**Status:** Pre-Optimization Root-Cause Audit  
**Navigation Library:** Jetpack Navigation Compose `2.8.9` (`androidx.navigation:navigation-compose`)  
**UI Toolkit:** Jetpack Compose BOM `2024.09.00` + Material 3 + Lifecycle Runtime Compose `2.8.7`

---

## 1. Audited Navigation Inventory (Actual Routes & Tabs)

Inspection of `app/src/main/java/com/example/ui/AppNavigation.kt` and `MainActivity.kt` shows the following actual tab and screen structure:

### Primary Bottom Bar / NavigationRail Tabs (`primaryNavItems`, `AppNavigation.kt:185-191`)
1. `dashboard` — Home
2. `daily_practice` — Daily
3. `coach_practice` — Coach
4. `speaking_lab` — Record
5. `ai_mentor` — Mentor

### Extended Sidebar & Secondary Primary Destinations (`SpeakCraftIndigoSidebar` & `NavHost`, `AppNavigation.kt`)
6. `learning_paths` — Learn (Learning Paths Overview)
   - `learning_path_detail/{programId}` — Program Detail
   - `learning_path_lesson/{programId}/{lessonId}` — Lesson Studio
   - `learning_path_assessment/{programId}/{moduleId}` — Module Assessment
7. `activity_library` — Activities Discovery
   - `activity/{activityId}` — Universal Activity Runner
8. `vocabulary` — Tools / Vocabulary Builder (including Daily Set, Flashcards, Saved Bank, Pronunciation Quiz, Weekly Quiz, Add Custom Word)
9. `analytics` — Analytics / Progress (`AnalyticsScreen`, `AnalyticsAndSettingsScreens.kt`)
10. `profile` — User Profile (`UserProfileScreen`)
11. `settings` — Settings (`SettingsScreen`)

### Specialized Drill-Down & Feature Routes
- `labs` (Interactive Labs hub), `frameworks` (Communication Frameworks), `video_modules` (Video Training Modules), `real_world_challenges` (Real-World Challenges), `admin` (Admin Dashboard)
- Deep links in `MainActivity.kt`: inbound Gemini Coach links, shortcut URIs (`speakcraft://daily_practice`, `speakcraft://vocabulary`, `speakcraft://speaking_lab`, `speakcraft://ai_mentor`), Notification Drawer destinations.

## 3. Target Architecture & Verification Plan

1. **Multi-Back-Stack Nested Navigation (`AppNavigation.kt`)**
   - Define 11 nested tab graphs:
     - `tab_dashboard` -> `dashboard`
     - `tab_daily_practice` -> `daily_practice`
     - `tab_learning_paths` -> `learning_paths`, `learning_path_detail/{programId}`, `learning_path_lesson/{programId}/{lessonId}`, `learning_path_assessment/{programId}/{moduleId}`
     - `tab_activities` -> `activity_library`, `activity/{activityId}`
     - `tab_coach_practice` -> `coach_practice`
     - `tab_speaking_lab` -> `speaking_lab`, `labs`, `frameworks`, `video_modules`, `real_world_challenges`
     - `tab_vocabulary` -> `vocabulary`
     - `tab_ai_mentor` -> `ai_mentor`
     - `tab_analytics` -> `analytics`
     - `tab_profile` -> `profile`
     - `tab_settings` -> `settings`, `admin`
   - Unified `navigateToDestination(route)` helper maps any route to its owning tab graph:
     - Switching to another tab navigates to its `tab_*` graph with `popUpTo(navController.graph.findStartDestination().id) { saveState = true }`, `launchSingleTop = true`, `restoreState = true`.
     - Re-tapping an already-active tab pops up to that tab's root start destination (`inclusive = false`, `launchSingleTop = true`).
     - Intra-tab navigation (`learning_paths -> learning_path_detail/... -> learning_path_lesson/...`) pushes normally onto that tab's preserved back stack.
     - Cross-tab deep navigation (e.g., Dashboard -> `learning_path_lesson/...`) switches to the owning tab graph cleanly while preserving source tab state.
2. **Thread & Lifecycle Hygiene**
   - `LearningProgressManager` & `NotificationManagerRepository`: IO-dispatched `loadForUserAsync` and optional `ioScope` / `ioDispatcher` in `AppContainer` (keeping synchronous fallback for deterministic JVM unit tests).
   - `InteractiveCoachViewModel`, `MainCoachViewModel`, `LearningPathsViewModel`, `ActivityEngineViewModel`: background dispatchers, deduplicated sync, session preservation (`forceReset = false`), non-destructive `SpeakingAndLabsViewModel.onCleared()`.
   - UI screens: `PhoneGeminiBridge` / catalogue lookups moved off composition onto ViewModel flows or `LaunchedEffect(..., Dispatchers.IO)`; `rememberSaveable` across all filters, tabs, search queries, drafts, and accordion expansions.
3. **Automated Verification**
   - Add `app/src/test/java/com/example/NavigationPerformanceAndStateTest.kt` covering nested tab switching (`Learning Paths -> Program Detail -> Module 2 -> Vocabulary (switch sub-tab) -> Learning Paths` restoring Program Detail & Module 2), tab re-tap pop-to-root, active-tab hierarchy matching, unfinished activity preservation, and deduplicated sync.
   - Verify full `:app:compileDebugKotlin`, `:app:compileReleaseKotlin`, `:app:testDebugUnitTest --no-daemon`, and static CI policy checks.
